After these, Phase 1 is accepted (no further round); Windows-only code is verified by the first CI windows-latest run.

M1 **Store I/O can't strand the forwarder** (R3-SEC-03, P3-01, GO3-01). Every item read/write runs off the main control path with the existing deadlines: a read that doesn't return in time is "not ready / unavailable" for that attempt (serve stays responsive, EOF and signals still shut down within the 10 s deadline; a stuck read goroutine is abandoned, never awaited past the deadline). Test with a store fake that blocks forever.
M2 **Key verbs are bounded end to end** (R3-SEC-04, P3-04, GO3-02). The 30 s verb deadline covers reading stdin, taking the per-connection lock, and the store I/O; on expiry the verb exits with the documented busy/timeout code, releases the lock (lock is tied to the process/handle, not held by a stuck goroutine), and writes nothing after the deadline. `key set` with stdin never closed → timeout, nothing written.
M3 **Receipts tell the truth** (R3-SEC-01, P3-02, GO3-03). Exit 7 ("nothing was written") only when the item provably wasn't replaced (re-read shows the old fp@rev); if a rename/flush/sync error comes after the new file may have taken effect (NFS, EIO), re-read and report `ok` if the new item is in place, else `unconfirmed` — never "nothing changed" for a write that happened. Test: inject an error after rename for each verb (set, retarget, delete).
M4 **Windows delete is durable before the receipt** (R3-SEC-02, GO3-04): flush the directory/file handles as the plan's Windows write path does (or report `unconfirmed`); test in the Windows suite.
M5 **Deadlines use the monotonic clock** (P3-03): stall/shutdown timers use `time.Since`/timers on monotonic time, never wall-clock comparisons; test with an injected wall-clock jump.
M6 **macOS ACL check through libSystem** (lens judgments in all three): replace the raw syscall numbers with libSystem-bound `getattrlist`/`fgetattrlist` the way x/sys/unix binds libc on darwin (`//go:cgo_import_dynamic` + trampoline, still CGO_ENABLED=0). If that proves impractical, keep the raw call but fail closed (`denied` with the rule named) on any unexpected errno and add a CI test on the newest macOS runner — say which you did.
