## High — access, keys, accounts
W1 **The screen the user edits is the grant that's minted** (UX-01, SEC-01, P3-R2-01, Q2-01). The manual sheet is prefilled from the live reconnect values (grant, absolute expiry) when reconnect lands on manual; on Create key the visible access is snapshotted and used. A pending key is reused only if it matches that snapshot; otherwise it is released and a new one minted. The previous attempt's snapshot is used only to redeliver an already-minted key unchanged.
W2 **"Key gone" only on confirmed absence** (UX-02, SEC-02, P3-R2-02, Q2-02). Manage ▸ Replace/Reconnect needs a successful lookup: pending → wait for it; failed → retryable lookup error, no Replace. `keyGone` is set only when a successful lookup shows the key absent or expired; otherwise the pre-mint live-access re-read always runs.
W3 **Same-key intent survives a Replace preview** (UX-03, P3-R2-01). Continue → settings-file fallback that meets a foreign entry keeps `sameKey` plus the record's grant, expiry, name and tier through the preview; Replace adds only the consent for the displayed target + digest. Never mints, never revokes the working key.
W4 **Manual reconnect is safe** (UX-04, UX-05, SEC-02, SEC-06, P3-R2-03, Q2-03). A manual record stays on the manual path through reconnect, including when the old key is already gone. Before minting, it needs a fresh, usable manual plan: key-bearing step or Claude key-file preparation, and the same target. Prerequisite-only or refused plans show the reason + Check again, with no mint. "I've updated" needs a usable loaded plan. Immediately before recording, it re-reads the old key's grant and expiry; if they changed, it releases the replacement and shows the current access, and the user copies the corrected key again.
W5 **No manual rotation over a running CLI candidate** (SEC-03, P3-R2-07). While the record has a running/unconfirmed candidate, manual reconnect/confirm is refused with "<App> is still saving the previous key — try again in a moment" (no mint). Test against the real `recordManual` reply shape.
W6 **Account and cancel checks at every side effect** (UX-06, Q2-06, SEC-04, SEC-05, P3-R2-05, P3-R2-06, Q2-04, Q2-05).
- Before every account RPC (CreateApp, ListApps, RevokeApp) and after every await, check `alive(op)` and the originating account, including right after `dropPending` and before minting.
- A late CreateApp success that can't be resolved under its own account is kept in module memory only, never MobX or Storage, as `{ accountId, key }`. It is looked up and revoked when that account is active again; until then the cleanup hint is shown.
- A committed apply/recordManual reply under a changed account keeps main's committed state, but doesn't touch the store, probe or advance the popup; follow-ups wait for that account's next check.
W7 **Stale retry never adopts another record** (P3-R2-04). On `stale`, the attempted record is invalidated. A first connect that now finds a record at the target opens that record's Manage. A reconnect whose record changed or vanished reloads Manage (or closes) and needs a new decision. No `expectedHash` switches silently.
W8 **Claude manual preparation is bound to the displayed plan** (P3-R2-09, UX-10). The delivery plan used by `createManual`/`connectIn` (`manual: true`) is validated: same canonical target as the displayed one, usable manual steps, not refused. A key-file write always sends a bound `previewTarget`. A changed or refused plan → back to the screen. A foreign key file offers a manual Replace preview, whose approved target + digest are carried into `aiConnectApply({ manual: true, replace })`.

## Medium — flows and states
W9 **Promoted replacement finishes cleanly** (SEC-07, P3-R2-08). After a check that settles a delivery, process the hashes newly revocable in the check reply once (still excluding running candidates), and probe the promoted key, before polling ends.
W10 **Manual reconnect sends `connectionId`** for every record (P3-R2-10); a moved target is an explicit location choice before any replacement key is shown.
W11 **Close cancels synchronously** (P3-R2-11). The popup's `onClose` requests cancellation and invalidates polls; unmount cleanup stays idempotent. Test a poll reply between close and unmount.
W12 **Finishing follows the current status and the followed hash** (UX-08, UX-09, P3-R2-12, Q2-07). Install poll: route from a successful check's current status first (accessEnded/conflict/removed → their actions), acknowledge only a currently valid install. CLI: track the hash this attempt delivered; once main confirms it, show its next step even if an older candidate is retained; when polling stops unresolved, offer Check again.
W13 **Previews are bound to their request** (UX-07, UX-11, SEC-08, P3-R2-13, Q2-10). Each preview has a sequence number and the route, tier and port it was requested with; only the latest reply can enable submit. Key-bearing manual snippets are bound to their port. If the port changed, regenerate the instructions and require confirmation before Copy or record. Other-app immediate success renders the fresh plan's steps.
W14 **Every save failure has a retry** (UX-12, UX-13, SEC-10, P3-R2-14, Q2-08). Manual view: the unsaved notice + Save again, independent of the file-mode notice; manual probe failure shows Retry check. Finish: `ackFailed` renders before the step-specific controls (incl. confirmInApp), and Retry repeats only the acknowledgement.
W15 **Gallery feedback** (UX-14, P3-R2-15, Q2-09). A failed first check (after a successful list) shows the failure + Scan again with rows kept; the row's Retry check shows its own lookup/probe error (still probe-only).
W16 **Restart target name everywhere** (UX-15, Q2-11): the preview, manual finishing step and Manage tier notice use the resolved restart target (ChatGPT for the shared Codex file).
W17 **No Open for CLI cards** (UX-16): hide Open where main has no launch target (Claude Code, Codex CLI, Linux).
W18 **Focus** (UX-17, P3-R2-16, Q2-12). Manage's editors focus their first control on open and return focus to Change on cancel/save. The Tab containment works at the document level while this popup is topmost, so focus that escaped is brought back. Gallery action buttons get the existing focus-visible outline.
W19 **Reveal after disconnect** (UX-18): the result keeps the leftover path; Reveal only when the approved IPC target resolves to it, else Copy path.
W20 **Store belongs to an account** (SEC-09): `S.AiConnect` records its account and is cleared on logout (where other account stores are cleared); retained-on-failure data is shown only for the same account. (Phase 4's startup reaction will reuse this.)
W21 **Disconnect confirms what it showed** (SEC-11): the confirm passes the captured connection id + hash; `stale` → reload Manage and confirm again.
W22 **Ollama footer** (Q2-13): the action row wraps/stacks; add an all-four-installed story.
W23 **Sentinel covers desktop Storage** (Q2-14): capture Storage's write API / fake `electron().storeSet` too.
