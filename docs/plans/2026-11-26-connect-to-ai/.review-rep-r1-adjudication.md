# Claude extension Replace (commit 5e1a36ff01), review round 1: adjudication (orchestrator)

Raw: scratchpad `reviews/rep-r1/out1.md`, `out2.md`, `out3.md` (gpt-6.2-astra xhigh; 1 main process, 2 renderer, 3 adversarial). No critical findings. The 20+ findings merge into R1–R16. Each accepted item gets a regression test named "R<n>: …".

## ACCEPT

R1 **High. Don't revoke the old key until its entry is gone** (lens1 H1, lens3 L3-01). Today the first save puts the old config key's hash in `revokePending` while the settings file still holds that key. A crash while waiting for Claude to quit, or a failed removal plus a failed `Registry.revert`, revokes the key Claude still uses, and the entry then blocks Open again. Fix:
- Persist the replacement as pending, keeping the prior record and both hashes. The old hash is not revocable.
- Promote the old hash to `revokePending` only after the removal succeeded.
- On start, recover an unfinished replacement before the revoke queue drains.
- If the revert can't be saved, apply must not report success.
Tests: a restart right after the first save; a failed removal plus a failed revert.

R2 **High. The crash window after `upsert` leaves the new key untracked** (lens1 H2). In an own-entry rotation, `upsert` saves the new record and consumes its mint intent. If Anytype exits after the registry rename but before `.txn` is deleted, startup restores only the old record. Fix: the durable undo carries the consumed intent (or the exact new hash), and recovery restores it with the old record, so the never-delivered key is revoked. Test the crash between rename and `.txn` delete.

R3 **High. One late locked check before copying or opening, always** (lens1 H3). Today, if the agreed entry is absent at the first locked read, `removeEntry` is skipped, and an entry restored before the save is never checked again. Fix: under `configLock`, immediately before the key is copied and the bundle opened, always check the entry:
- absent → go on;
- equal to the consent → remove it;
- anything else, or another target → revert.
Keep the window from that check to the open as short as possible. Test: the entry disappears at the first read and reappears before the save.

R4 **Never quit Claude without quit consent** (lens1 M1, lens2 L2-02, lens3 L3-02; three lenses). The branch that sends the quit signal checks `ctx.allowQuit`; without it, return `needs: 'quitApp'`. Test: Claude stopped at `quitNeeded`, then running at the next lookup.

R5 **Re-check that Claude isn't running before every rename attempt, retries included** (lens1 M2). Windows `writeFileSafe` retries a busy rename after a sleep, and Claude can start in between. Add a pre-rename callback that re-checks the process state on every attempt. A running Claude aborts the write and reverts. Use it for this removal and for the settings-file route's writes, which share the writer.

R6 **Don't offer Replace for an entry the writer can't remove** (lens1 M3). For example, two `anytype` members under `mcpServers`. Dry-run `CONFIG.remove(t.text)` in plan and in apply before minting or quitting. A failed dry run keeps today's refusal (manual), with an accurate note.

R7 **`keyCopied` only for the record's own raw key** (lens1 M4, lens2 L2-06, lens3 L3-06). Match the guarded copy's text fingerprint against the record's key fingerprint as well as its owner. A copied config snippet, or an earlier key of the same connection, never counts. Don't read the system clipboard for this. Instead, word the notice as a past copy: "Your key was copied to the clipboard. Paste it when %s asks for it. …". Another profile overwriting the clipboard is an accepted residual.

R8 **A Claude settings-file or manual record can switch to the extension from its card** (lens1 M5, lens2 L2-01 high, lens3 L3-04). Add a "Use Claude's extension" action in Manage when the record is `config` or `manual` and a usable bundle exists. It opens the package preview with the current record as the expected owner, keeping grant and expiry. The Replace consent from R1–R3 then applies. Test it from the gallery entry point, without forcing `view: 'connect'`.

R9 **An entry that appears between plan and apply re-plans** (lens2 L2-03, lens3 L3-05). Re-plan a Claude package `validate/conflict` even when the previous preview had no entry. Keep the pending key, show the new Replace preview, and keep `openFailed` if Claude also failed to reopen.

R10 **The Finish clipboard state stays in sync both ways** (lens1 L3, lens2 L2-04/L2-05, lens3 L3-07). Main returns the guarded copy's expiry with `keyCopied`. The renderer arms its timer for the remaining time on resume and reconciles both directions on every successful check, so a copy from another window shows as copied. The lost-Apply-reply path takes `copyFailed` from the recovered record instead of hardcoding `true`.

R11 **Configure reports a failed relaunch** (lens1 L1, lens2 L2-07, lens3 L3-08). `deliver()` propagates `relaunch()`'s result. Finish shows the existing start-Claude notice on the Configure path, which today suppresses `openFailed`.

R12 **Clear old ownership when a record moves to the package method** (lens1 L2, lens3 L3-09). Clear `entryDigest` and `configPath` on every successful transition to `package`. Extend the gone-entry test to start from a managed config record.

R13 **The development hint only for a known development build** (lens1 L4, lens3 L3-10). `devBuild` only when the metadata says `signed: false`. Missing or malformed metadata gets the reinstall text.

R14 **An accurate development recovery text** (lens2 L2-09, lens3 L3-11): "Development build: run ./update.sh <platform> <arch> (e.g. macos-latest arm64) or set ANYTYPE_MCP_BIN, then rebuild with bun run build:electron and restart." Check update.sh's real argument names.

R15 **The switched-off extension wording** (lens2 L2-08). For `off`, tell the user to paste the new key in the extension's Configure (Settings ▸ Extensions ▸ Anytype), then switch it on. Keep the install-dialog wording for the install dialog only.

R16 **Pin consent after Claude's shutdown rewrite** (lens3 L3-12). The fake quit changes the entry before reporting exit. Assert that the changed entry survives, the previous record and intent return, and no key is copied.

## REJECT / RESIDUAL

- lens3 L3-03 (cross-profile reservation through the whole install hand-off). After R3, the gap is the time between the last locked check and the user confirming Claude's install dialog. Closing it needs a cross-process reservation that every config writer honours: new shared state for a rare case (two Anytype profiles connecting the same Claude at once). If it happens, both routes are visible and the existing both-routes detection tells the user to remove one. Accepted residual.
- Another profile overwriting the clipboard after our copy (part of L3-06): we don't read the clipboard. The past-tense wording (R7) and "Copy key again" cover it. Accepted residual.
