# Phase 2 code review, round 1 — adjudication (orchestrator)

Raw: scratchpad `reviews/p2-r1/lens1.md` (correctness, P2-xx), `lens2.md` (security, SEC-xx), `lens3.md` (robustness, Rxx), `lens4.md` (quality/tests, Qxx). ~70 findings → the themes below. ACCEPT every theme; read the raw findings for reproduction details. Each fix gets a regression test on the production path. Keep fixes simple.

## High
T1 **Claude extension signer gate** (P2-01, SEC-01, R02, Q02). A KNOWN signer mismatch (from `extensions-installations.json`) wins over an unreadable/missing enable-settings file: never write the key file for a wrong-signer or unverifiable extension on a signed build; reopen the signed bundle instead.
T2 **Committed delivery + registry save failure** (P2-02, R01, Q01). Once the target write committed, a registry save failure must NOT be reported as "not committed" (the renderer would revoke a key that is installed). Return an explicit `committed: true, recordSaved: false` outcome (or retry the save, then report it) so the key is kept; the next check/repair re-records it. Test: inject a registry save failure after a successful write.
T3 **Claude Code profile mixing on update/heal** (P2-04, SEC-03, R04, Q04). Updates, heals and skill refreshes write only to the profile the RECORD was created for (persisted canonical config path); if the currently resolved profile differs → `conflict`/manual, never copy the key into the new profile.
T4 **Writer retry must not undo a user deletion** (P2-07, SEC-08, R03, Q05). On `changed` → re-plan: if our owned entry was present in the original snapshot and is now absent, the user removed it → stop with `removed`, do not re-add. Only a first-time insert (originally absent) may retry.
T5 **Revocation set for unconfirmed rotations** (SEC-07, R05, Q03, P2-03, R06). A second indeterminate/unconfirmed rotation unions hashes (never drops the first pending hash); reconciliation for an unconfirmed CLI delivery reads the same verified profile file the CLI wrote and keeps whichever key is installed (never revoke the installed one). Claude Code: after a CLI failure, report the real state (old entry still present / removed / new present) based on a re-read.
T6 **Manual Claude Code command without argv secrets** (P2-06, SEC-02, R09, Q07). The manual snippet uses `claude mcp add-json --scope user anytype -` and tells the user to paste the JSON on stdin (then Ctrl-D) — no key in argv or shell history. Same idea for any other manual CLI snippet (prefer file/JSON paste over a key in a command line).
T7 **Claude Desktop config route on Linux / MSIX / unknown running state** (P2-05, R07, Q06, R08). When the running state is `unknown` (Linux without a known exe, MSIX, failed process query), offer the user an explicit "I've quit Claude — continue" confirmation, then re-check what can be checked and proceed. A failed Windows process query is `unknown`, never `stopped`. Fix the Linux restart fixture to match what production detection really supplies.
T8 **Claude Code ownership includes owned fields** (P2-08, SEC-06). A matching bearer is not enough: the entry's non-key fields Anytype wrote (type, url form) must match too; otherwise `conflict`.

## Medium
T9 **Codex home freshness** (P2-09, R10). Re-resolve homes (or invalidate the detection cache) before apply/update; never write to a home that is no longer the resolved one.
T10 **Claude Desktop replace + rollback + launch errors** (P2-10, P2-13, R12, R13, Q10). An approved cross-account replacement must be completable (or not offered); rollback and relaunch failures are reported (`left`, error) instead of swallowed; the test asserts the leftover result.
T11 **Preflight must match the writer** (P2-11, R14, Q09). `plan()` runs the same shape checks as the writer on the previewed bytes (unsupported forms, unparseable) so it never approves a write that will fail.
T12 **Manual Claude Desktop preparation** (P2-12). "Set up manually" for Claude Desktop only prepares the key file and Reveal of the bundle; it must not run the automatic config/quit workflow.
T13 **Health of owned wrapper entries** (P2-14, R15, Q12). An owned Claude wrapper entry whose command/args point to a missing/old Anytype path is not healthy: heal it (if Claude is not running) or report `attention`.
T14 **Status on failed lookups** (P2-15, R16, Q08). A failed `ListApps` (or other lookup) keeps the last known status (`accessEnded` stays), never flips a revoked connection to healthy.
T15 **Port heal persists the port** (P2-16). After healing an entry to a new port, the record's `port` is updated.
T16 **Manual instructions must produce a readable config** (P2-17). Verify each manual snippet against the adapter's own entry shape (same `entry()` function) and the client's file format.
T17 **Quit correctness** (P2-18, R11). Quit succeeds only if no matching process remains (re-list after exit, including a relaunched instance) and respects its deadline.
T18 **Windows LM Studio deeplink** (P2-19). Make the Windows handler-path match reachable (or explicitly disable the deeplink on Windows and use the file route) — no dead code path.
T19 **Skill cleanup confinement** (SEC-04). Deleting the skill file/dir only inside the resolved skills dir under home (canonical check), never follow links out.
T20 **Claude Code write path = checked path** (SEC-05). Preflight, CLI run and readback use the same canonical profile file (env + HOME as in Phase 1 fix 3).
T21 **Reused keys from loose files** (SEC-09). Don't reuse a key read back from a file writable by group/other (POSIX) for healing; report `attention` instead.
T22 **Windows bundle launcher identity** (SEC-10). Launch only the verified Claude package/exe (package family / publisher check), else Reveal guidance.
T23 **Reveal paths** (SEC-11). Reveal only local absolute paths inside home (`isLocalAbsolute` + canonical check); never UNC.
T24 **Route switches keep ownership data** (R17). Switching route (e.g. skill ↔ MCP, package ↔ config) preserves what's needed to clean up the previous route's artefacts.
T25 **Test quality** (Q11, Q13, Q14, Q15, P2-20). The restart timing test measures real behaviour (fake clock or bounded poll assertions); the sentinel sweep asserts the sensitive operation actually ran; add the two Codex sharing cases from the plan; the "old CLI entry still present" test starts with an entry.
