## Key findings / gotchas

1. The published `anytype-api` skill hardcodes `http://127.0.0.1:31009` and says "Every call sends Authorization: Bearer <key>" with no env-var name (live fetch; small-model summary, verify by reading the file). Zero-touch therefore needs either a Anytype-authored variant of the skill (reads $ANYTYPE_API_KEY / $ANYTYPE_API_URL, uses `curl -H "Authorization: Bearer $ANYTYPE_API_KEY"`) or a wrapper CLI. The skill also says keys are minted in-app only ("the API mints none") - consistent with our in-app mint.
2. Skill install dir cheat-sheet (vercel-labs/skills docs/agents.md, CONFIRMED, plus per-vendor docs): ~/.agents/skills (Codex, Zed, Warp, Cline, Pi...), ~/.claude/skills, ~/.cursor/skills, ~/.copilot/skills, ~/.config/opencode/skills, ~/.config/goose/skills, ~/.codeium/windsurf/skills, ~/.kiro/skills, ~/.factory/skills, ~/.hermes/skills, ~/.config/agents/skills (Amp), ~/.gemini/config/skills (Antigravity), ~/.gemini/skills (Gemini CLI). Writing ~/.agents/skills + ~/.claude/skills covers Codex, Cursor, Copilot, OpenCode, Droid, Windsurf(per Devin doc), Zed, Gemini CLI, Claude Code. Antigravity is the outlier.
3. Gemini CLI is dead for consumer accounts (since 2026-06-18). Target Antigravity CLI instead; its env/sandbox story is undocumented here.
4. Claude Code: env block is the cleanest (works for CLI, IDE, Desktop; live reload). Best-in-class secret handling: `sandbox.credentials.envVars` with `"mode": "mask"` replaces the var with a sentinel in the sandbox and injects the real value only on allowed hosts (CONFIRMED in sandboxing doc; whether it works for a loopback destination: UNCONFIRMED); `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` strips credentials from subprocesses (note: would break our own var if applied).
5. Codex: key `set` survives the *KEY*/*TOKEN* default filter. But network off by default in workspace-write and loopback is blocked even with proxy -> must set `network_access = true` or `allow_local_binding`. This is the main friction; prompt/approval each curl otherwise.
6. Sandboxes on by default today: Cursor (Auto-review). Off by default: Claude Code, Copilot CLI, Hermes, probably OpenCode. Codex always sandboxed.
7. Secret exposure: no agent redacts a var it injected. Mitigations: (a) skill instructs `curl -H "Authorization: Bearer $ANYTYPE_API_KEY"` and forbids echo/-v/printenv; shell expands it, though the model's command text shows the name not the value, but output of `curl -v`, `env`, or `set -x` leaks it into transcript/logs; (b) preferred: bundled `anytype` CLI reading ANYTYPE_API_KEY itself, never printing it; add skill rule "never print env"; (c) even better, CLI reads key from a 0600 file/OS keychain so no env var is needed at all and only the CLI path allow-rule is required (Claude `Bash(anytype *)`, Codex prefix rule). Hermes content-check flags secret-carrying curl args; Gemini redaction off by default.
8. Scoped key + read/write choice in Anytype is the real blast-radius control; plan for key revocation UI.
9. Plugin routes: Claude Code plugins (skills/ dir; /reload-plugins for hooks/mcp), Codex plugins (shared ChatGPT/Codex directory), Cursor plugins (.cursor-plugin/marketplace.json), Droid plugins (skills/, ${DROID_PLUGIN_ROOT}), Antigravity plugins (~/.gemini/config/plugins/). Plugins can't carry a per-user secret, so env/settings injection is still separate. Direct file drop into global dir is simplest and was confirmed for all above.

## Precedent (Q5)
- vercel-labs/skills (`npx skills add <src> -g -a <agent>`) auto-detects installed agents and writes to the per-agent global dir; supports ~75 agents (CONFIRMED). No credential injection. Anytype's own `npx skills add https://developers.anytype.io --skill anytype-api` already works as install channel.
- Credential+skill auto-install by a desktop app: no clear precedent found live (UNCONFIRMED; did not search Linear/Sentry/Stripe/Obsidian specifically). Hermes' `required_environment_variables` and Claude plugins' config prompts are the closest in-agent mechanisms.
