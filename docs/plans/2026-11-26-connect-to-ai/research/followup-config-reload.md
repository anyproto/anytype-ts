## Details and sources

### Cursor
- Forum thread "MCP server regression - does not reload tools, 'disconnect' does nothing, ignores mcp.json changes" (reports Jul 21 2026, staff replies through Aug 25 2026; versions 3.11.25 ok, 3.12.17, 3.12.30, 3.17.8 Linux): non-stdio servers do not refresh on mcp.json change or reconnect; staff: known bug, tool list cache not cleared; `list_changed` re-list regressed in 3.12.17; only full restart reliable; workaround of changing a hashed key (e.g. dummy URL query) forces client rebuild. https://forum.cursor.com/t/mcp-server-regression-does-not-reload-tools-disconnect-does-nothing-ignores-mcp-json-changes-etc/166216
- Implication: write the file, then say "Quit and reopen Cursor". Also: a NEW server entry may show up without restart (older observed behavior, UNCONFIRMED); do not promise it. Project-level `.cursor/mcp.json` had separate bugs on 3.12.30; use the user-level file.
- Windows/Linux paths: official docs only show `~/.cursor/mcp.json`; VS Code's MCP config reference lists `~/.cursor/mcp.json` as Cursor's user path too (https://code.visualstudio.com/docs/agents/reference/mcp-configuration, fetched 2026-11-27). Windows expansion `%USERPROFILE%` unconfirmed in Cursor docs.

### LM Studio
- Docs (https://lmstudio.ai/docs/app/mcp, fetched 2026-11-27): no path, no reload statement; "Program tab > Install > Edit mcp.json"; MCP since 0.3.17 (b10).
- Blog 0.3.17 (https://lmstudio.ai/blog/lmstudio-v0.3.17): "When you save the mcp.json file, LM Studio will automatically load the MCP servers"; recommends the in-app editor; paths `~/.lmstudio/mcp.json`, `%USERPROFILE%/.lmstudio/mcp.json`.
- Issue lmstudio-bug-tracker #1371 (opened 2026-01-14, still open, 0.3.33 macOS): docs path wrong; file actually at `~/.cache/lm-studio/mcp.json`. The thread itself does NOT mention the pointer; pointer evidence stays with prior report (local machine file `~/.lmstudio-home-pointer` containing the real home dir, and issue #2015 Windows pointer location in the user profile).
- Issue #2518 (Bionic 1.1.8): Bionic has separate `~/.lmstudio/apps/bionic/mcp.json` and `ng-mcp.json`; "Settings > MCP" reads a different file than the agent. So do not assume Bionic reads the main mcp.json.
- Resolver order for Anytype: read `<userprofile>/.lmstudio-home-pointer` (first line = home dir) -> `<home>/mcp.json`; else `~/.lmstudio/mcp.json`; else `~/.cache/lm-studio/mcp.json` (macOS reality). Windows/Linux relocation otherwise unconfirmed.
- Reload: treat as needing toggle/restart. Safest write: edit the file while LM Studio is closed, or tell user to open Program > Install > Edit mcp.json and press save once (that save path is the documented auto-load). Suggest test on real builds before shipping copy "Done".

### VS Code / Copilot
- VS Code 1.148-era docs (fetched 2026-11-27): new native Copilot config = `$COPILOT_HOME/mcp-config.json` or `~/.copilot/mcp-config.json`, top-level `mcpServers`; workspace `.mcp.json` also; "For new Copilot configurations, use these native destinations, not .vscode/mcp.json or profile mcp.json" (those belong to the deprecated Local harness). `code --add-mcp` and "open mcp.json" commands target the editor-managed file, not the portable one. https://code.visualstudio.com/docs/agents/reference/mcp-configuration and https://code.visualstudio.com/docs/copilot/customization/mcp-servers
- Docs state no reload behavior and no minimum VS Code version (the page links to harness requirements). Min version for the native `mcp-config.json` path: UNCONFIRMED (docs version string seen: 1.148). Treat as "current VS Code"; keep user-profile `mcp.json` (`%APPDATA%\Code\User\mcp.json`, `~/.config/Code/User/mcp.json`, `~/Library/Application Support/Code/User/mcp.json`) as fallback for older VS Code (prior report; not re-verified).
- Remote/WSL/Dev Container: home dir where the harness runs is used; the desktop `~/.copilot` is not forwarded and 127.0.0.1 is not the host's anyway.
- Copilot CLI changelog (https://raw.githubusercontent.com/github/copilot-cli/main/changelog.md): "MCP server reload summary" on trust/resume; `/mcp` Ctrl+S saves with server reload; v1.0.93 (2026-10-07) config applies between turns (per prior report). CLI handles missing/symlinked mcp-config.json.
- VS Code `mcp.json` (editor-managed) historically offers Start/Stop/Restart CodeLens and reacts to saves, but the 2026 docs do not restate it: UNCONFIRMED for external write.

### Codex
- Path: source `codex-rs/utils/home-dir/src/lib.rs` (openai/codex main, fetched 2026-11-27): `CODEX_HOME` if set (must exist and be a dir) else `dirs::home_dir()/.codex` => Windows `%USERPROFILE%\.codex`, Linux/macOS `~/.codex`. CONFIRMED by source.
- Reload: `codex-rs/app-server` exposes `config/mcpServer/reload` (README "MCP configuration reload"; core `refresh_mcp_servers`), which refreshes loaded threads; no file watcher found. Issue openai/codex #3860 (closed 2026-11-17) = "manual edits to config.toml don't reliably reload" feature request. Official page https://learn.chatgpt.com/docs/extend/mcp: desktop Save then Restart; IDE Restart extension. UX: "Restart Codex (or start a new session)". Whether a running Codex Desktop/IDE app calls the reload RPC on external file change: UNCONFIRMED (assume no).

### Kilo
- Docs https://kilo.ai/docs/automate/mcp/using-in-kilo-code (fetched 2026-11-27): global `~/.config/kilo/kilo.json|kilo.jsonc`; project `./kilo.json(c)` or `./.kilo/kilo.json(c)`; key `mcp`, entries `type:"remote"`, `url`, `headers`, `enabled`, `timeout`. No restart/reload statement, no Windows path.
- Source (Kilo-Org/kilocode main): `packages/core/src/global.ts` uses `xdg-basedir` `xdgConfig` + "kilo"; xdg-basedir v5.1.0 (`index.js`) = `XDG_CONFIG_HOME || os.homedir()/.config` with no Windows special-casing => Windows `%USERPROFILE%\.config\kilo`. `packages/opencode/src/config/config.ts` `refreshGlobal` + `kilocode/config/global-stamp.ts` re-reads config files and invalidates cached global config when content changed ("detect global config edits made by other Kilo processes"). Not a watcher; refresh happens when config is next read. Whether already-running sessions reconnect MCP servers: UNCONFIRMED.
- Recommendation: if a `kilo.jsonc` exists, merge into that file (JSONC-aware) rather than creating `kilo.json` (both are loaded; later files win).

## Copy / resolver recommendations
- "Done, no restart needed": not safe for ANY of the five. Use "Restart <app>" for Cursor and Codex (confirmed need), "Open a new chat / restart if not listed" for Kilo, "Toggle in Program tab or restart" for LM Studio, "Press refresh in MCP servers / new chat" for VS Code Copilot.
- Cheap trick for Cursor: because a changed hashed key forces client rebuild (forum workaround), write the entry with a distinct key; still require restart as the reliable path.
- Resolver: honor env overrides (`CODEX_HOME`, `COPILOT_HOME`, `XDG_CONFIG_HOME`); note GUI-launched Electron main may not see shell-exported env vars on macOS/Linux; use `os.homedir()` (= `%USERPROFILE%` on Windows).
- Test items before launch (all need a real build): Cursor new-entry behavior, LM Studio external-write behavior and pointer on Win/Linux, VS Code external-write and minimum version, Codex desktop external-write, Kilo live reconnect.
