# heart Phase 2 (anytype-mcp file tools) review, round 1 — adjudication (orchestrator)

Raw: scratchpad `reviews/heart-p2-r1/lens1.md` (SEC-xx, confinement/security), `lens2.md` (P2-xx, behaviour). All ACCEPTED unless listed under REJECT; simplest safe fix; one regression test per theme. Implementer verifies each finding against the code first and may reject a wrong one with a reason in the report.

N1 **No upload of a file that also lives elsewhere** (SEC-01): refuse a regular file whose link count is > 1 (Unix `Nlink`, Windows `NumberOfLinks` via the opened handle). Test with a hard link to a file outside the folder.
N2 **The files folder never overlaps Anytype's own folders** (SEC-02): refuse `--files-dir` equal to, inside, or containing `~/.anytype` (the item store) — compare canonical paths/handles; the temp default can't overlap by construction.
N3 **Private by construction, not by inheritance** (SEC-03, P2-02, SEC-05): created folders (temp default and a missing `--files-dir`) and every written file get a protected owner-only descriptor on Windows (user + SYSTEM + Administrators, inheritance off) and 0700/0600 on Unix; macOS/Windows folders carrying extended ACLs/inherited grants for others are refused (same rule as the store). Creating `--files-dir` must never change permissions of existing ancestors.
N4 **Validate what is pinned** (SEC-04, SEC-06, SEC-07, SEC-11, P2-09): open the folder once (os.OpenRoot), then run owner/mode/ACL/junction checks on that handle (Windows: by handle; Unix: fstat of the root), use the original absolute spelling without silent cleaning that changes the target, and report download paths built from the pinned root's path. Bind mounts nested inside the folder: refuse cross-device entries (st_dev differs from the root) on Linux/macOS for uploads.
N5 **Publish safely** (SEC-08, SEC-10, P2-05, P2-10): a download is published only by a no-replace operation (link/rename that fails if the name exists, retry next name); cancellation, shutdown or EOF before publication removes the part file and publishes nothing.
N6 **No bearer on disk** (SEC-09): a download body that contains the bearer (raw or JSON-escaped, as the K6/L5 check) is not saved; return an error.
N7 **Strict arguments and receipts** (P2-01, P2-07, P2-11, P2-12): `dry_run` must be absent or a boolean (`null` → argument error, never a commit); `width` validation matches the schema; receipt member names matched exactly; any `..` component refused as §13.1 says.
N8 **Small behaviour fixes** (P2-03, P2-04, P2-06, P2-08, P2-13): a refused metadata request stops before the content request; a tools/list cache or listing-page race can't route a call to the wrong tool; the post-headers receipt wait uses the transfer deadline, not 5 s; long heart errors are truncated as valid JSON; the two path tests accept supported spellings.
N9 **Windows `.anytype` created by the forwarder gets its own protected DACL** (from the CI run: a home readable by Users made a fresh `.anytype` inherit and the store refused it): when the forwarder creates `.anytype`/`ai-connect`/items folders, set an explicit protected descriptor (user + SYSTEM + Administrators); existing folders keep the L4 refusal with the rule named.
N10 **Windows CI shows what ran**: run the anytype-mcp Windows test job with `-v` for `./cmd/anytype-mcp/...` (or log skips) so the symlink/junction tests' run/skip status is visible.
