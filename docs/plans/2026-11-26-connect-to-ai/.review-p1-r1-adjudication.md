# Phase 1 code review, round 1 — adjudication (orchestrator)

Raw: lens1.md (correctness), lens2.md (security), lens3.md (robustness/cross-platform), lens4.md (quality/tests) in this folder. 57 findings → ~33 distinct. Fix ALL accepted items, plus the plan revision 4 "Phase 1 delta for the implementer (rev 3 → 4)" table in implementation-plan.md §0 (incl. the gRPC DevTools interceptor bypass for key-bearing RPCs). Keep fixes simple; add a regression test for each.

## Registry (all lenses)
1. Fresh registry only on ENOENT. Any other read error propagates: leave the cache uninitialised (next call retries), never write over the file. Corrupt/wrong-shape file → quarantine to `.broken`; if quarantine fails, abort the mutation and keep the original. (P1-01, SEC-08, R01, Q01)
2. Mutations build a candidate state, save it, and publish to the cache only after the rename succeeds. Same-instance failed-save-then-retry test. (P1-05, R02, Q03)
3. Validate every record's required fields + array element types at load; an incomplete row is quarantined (or the file is), not crash `defaultStatus`. (Q04)
4. `Api.setUserDataPath` → the service switches its registry (serialised in the queue). (R09)

## File writes
5. `Env.writeFile`: `fs.writeFileSync(fd, text, 'utf8')` on the exclusively opened fd, then fsync + close; rename only after all succeed. (P1-04, R03, Q06)
6. Key file write AND remove take an expected snapshot (incl. expected-absent) and recheck immediately before rename/unlink → `changed` on mismatch. No backup (as before). (P1-02, R05)
7. Re-validate the canonical parent directory (realpath equals the planned one, not a link) before creating backup/temp files and before each rename attempt → `changed`. (SEC-03, R04)
8. On a failed write, remove directories created by THAT attempt in reverse order (rmdir only if empty). Also when mkdir fails part-way. (P1-12, R13)
9. Bundle copy: copy to an exclusive temp in the verified key dir, refuse a linked destination, rename into place; the fake enforces the same contract. (SEC-04)
10. Bounded regular-file reads: LM Studio pointer (lstat isFile, ≤4 KiB, first line) and config snapshots (isFile, ≤ a few MiB); reject FIFOs/devices. (SEC-07)
11. JSON(C): one leading UTF-8 BOM is stripped for parsing/edits and restored. Own-property traversal only (`__proto__` safe): use `parseTree`/`getNodeValue` or `Object.prototype.hasOwnProperty`-guarded walks, and null-prototype objects where values are compared/digested. (R18, SEC-11)

## Key file & wrapper permissions
12. POSIX: the wrapper fails closed (same readable MCP error) if the key file or `ai-connect` dir isn't owned by the current uid or has any group/other permission bits; `keyFile.ts` checks the same before reuse. (SEC-05)
13. Wrapper and `plainProxyCommand` set `NO_PROXY=*` and `no_proxy=*` before importing the proxy (Node's env-proxy support would otherwise route the bearer through a proxy). (SEC-01 part)

## Probe
14. Replace `fetch` with `node:http` for the loopback probe (no "bad port" list, no env proxy), keep the 5 s timeout and no-redirect rule; transport-level test on a Fetch-blocked accepted port (e.g. 6000 or 10080) with a local test server. (P1-08, R11, Q09, SEC-01)
15. Capture `mcp-session-id` from the initialize response headers before reading the body; clean it up on every later error. (R12)
16. Record-bound probes: an automatic record whose `keyFp` doesn't match → `stale`, not success; manual records bind to the `appHash` captured before the request and persist `lastProbe` only if it still matches. Tests for both + rotation during the request. (P1-07, R10, Q08)

## Detection
17. Windows: drop `where.exe`; resolve executables in Node from `PATH` + `PATHEXT` (only `.exe` accepted for running), plus known dirs + App Paths; expand `REG_EXPAND_SZ` with a case-insensitive env. This fixes the cwd-search issue and non-ASCII decoding. (SEC-02, R16)
18. macOS: pass the expected bundle ids for Cursor, VS Code, LM Studio, Ollama (and any other app card) so `plutil` identity + `mdfind` relocation apply; test a relocated bundle and a same-named bundle with a wrong id. (P1-10)
19. Shell labels: when the login-shell output contains a label (even empty, e.g. `CODEX_HOME=`), it wins over the inherited process env; fall back to the process env only when the label is absent or the shell failed. (P1-11)
20. Non-POSIX login shells (csh/tcsh, fish): use a compatible invocation (fish: `-l -c`; csh/tcsh: fall back to `/bin/zsh -l` on macOS, `/bin/sh -l` on Linux) — pick the simplest; on failure keep `shellOk: false`. (R15)
21. `scanOk` reflects whether discovery actually completed (propagate helper failures instead of folding them into "not installed"); test a failed scan through the production-shaped interfaces. (P1-09, Q10)
22. Reject UNC (`\\server\…`) and device (`\\?\`, `\\.\`) paths from pointer files / env overrides before any fs call. (SEC-06)

## Codex identity
23. Each distinct canonical custom `CODEX_HOME` gets a stable id, e.g. `codex-home-<first 8 hex of sha256(canonical path)>`; `codex` stays the shared default; an existing record with the same canonical path is reused. Test custom A → custom B, both retrievable. (P1-03, R06, Q02)

## Service / IPC
24. Lazy init must not reset the queue: initialise env + registry outside `enqueue`/without replacing `this.queue`; test two overlapping calls on a fresh factory-constructed service. (P1-06, SEC-09, R08, Q05)
25. Validation: own-property checks for schema membership and required fields; build the result from declared fields only, into a null-prototype object (nested shapes too); tests with `toString` and `__proto__` keys. (P1-14, SEC-10, Q11)
26. Child processes: enforce the deadline — SIGTERM, then SIGKILL after a short grace for these short-lived CLI/shell children; return `timedOut: true` once the deadline fired, never `code: 0` after it. (GUI quits keep their separate graceful path.) (R07)

## Build & gate tooling
27. `build-mcp.js`: delete/invalidate old `mcpb.json` before replacing the archive; write the new metadata via a sibling temp and publish it last; `bundleInfo` compares the metadata digest with the archive and reports `signed: false` on mismatch. (R17)
28. Keycheck: exit non-zero on any unreadable dir/file or a file above the size cap (report only its path, with the key redacted from any printed path); no chunked scanning needed. (P1-13, SEC-12, R14, Q07)

## Tests
29. Typed fixtures: complete `AiConnection` fixture; use `satisfies` / explicitly typed variables for each IPC result variant so omissions fail typecheck in both tsconfigs. (P1-15, Q12)
30. Wrapper default-home tests set both `HOME` and `USERPROFILE`. (R19, Q13)
31. Extension-bridge test should use the real bridge object (export it from a side-effect-free module) if that's a small change; otherwise note why not. (Q14)

## Not accepted
- Chunked scanning of >512 MiB files in keycheck (fail as incomplete instead).
- The vendored proxy's own use of `fetch` (bad ports) — out of our control; note it as an anytype-mcp ask (use node:http) in the plan's asks.
