## High
A1 **Self-heal decides inside the queue** (all four lenses, P4-R2-01 / SEC-02). The Local API setting (enabled + port + bind outcome) is read INSIDE the queued service operation, immediately before an adapter may heal. A failed or unknown bind means offline. Test: hold the queue, submit a check, disable the API, release → the config file is byte-identical.
A2 **Back from the gallery is one ordinary step** (all four lenses). Back from an AI apps entry whose previous entry is version history (`main/history`) or anything else steps back exactly one entry, with no triple-redirect truncation, and Forward returns to the gallery with no sheet. Test through `keyboard.onBack`/`onForward` with `docA → docB → history → gallery`, asserting the full stack.
A3 **Every AI route spelling is canonical** (lens1 P4-R2-03, lens2 SEC-01, lens3 P4-R2-02, lens4 P4-R2-04). The registered `/main/aiConnect` fallback, the settings page chosen through query fields (`id=aiApps`, a percent-encoded action/id), and any other form that resolves to an AI destination get the AI field allow-list. The allow-list is applied AFTER resolving the effective page/action/id, at main ingress and in the renderer, before history, `updateTab` or saved tab state. The fallback's `app` is validated as a catalog id. Add these forms to the sentinel ingress → `redirectSet` → `Router.go` → `updateTab` test (assert the first `updateTab` call too).
A4 **Activation really retries** (lens3 P4-R2-04). Production tab deactivation pauses MobX reactions, so retry a pending/refused check from the existing `set-active-tab` handler, including an activation that arrives while the refused request is still settling. Test with `Common.isActiveTabSet` and the production scheduler.
A5 **Nudge keys don't reach the editor** (lens4 P4-R2-03). Keydown on the nudge's buttons (Enter, Space, Tab, Shift+Tab) must not trigger editor/global shortcuts, while native button activation and Tab focus movement keep working. Test: with an editable document's handlers installed, Enter/Space on the nudge buttons runs no block command, and Tab moves between the controls.

## Medium
A6 **A gallery visit belongs to its history entry** (lens1 P4-R2-04, lens3 P4-R2-05/06, lens4 P4-R2-06). Bind the pending target to the cleaned entry's history key. On leaving that entry (incl. Back between two gallery entries), discard the target and close the sheet it opened through the normal popup close. A direct `main/settings/aiApps?app=…` link without `spaceId` is cleaned to the route WITH the active space, so the keyed React route doesn't remount and lose the target. Test through the keyed route table.
A7 **Targets resolve after a successful reconciliation** (lens1 P4-R2-05, lens3 P4-R2-07, lens4 P4-R2-07). A failed first load → stop, keep the target, show Scan again. A connection target opens Manage only after a successful `check`; a failed check keeps the target + Scan again. Test both failure orderings separately.
A8 **A cold link doesn't take the tab's boot route** (lens1 P4-R2-06, lens3 P4-R2-10, lens4 P4-R2-05). Main passes the pending AI catalog id separately from the active tab's saved route (`getInitData`). The restored (pinned) tab boots to its own saved route; the gallery then opens as usual. Test a cold start with pinned doc A ≠ the space's last object B.
A9 **`void/empty` consumes the link** (lens1 P4-R2-07, lens3 P4-R2-09) once the account and space are ready and the PIN is unlocked. Loading, space selection and PIN keep waiting.
A10 **A held nudge re-checks everything** (all four lenses). Before showing a held claim: a successful list refresh (or no show), then re-evaluate API listening, candidate, account, focus, visibility and popups, reusing the claim. Test by changing only fake main's records (another window) and by disabling the API while the claim is held.
A11 **Shared-card link opens the owner's identity** (lens1 P4-R2-09). An app link that maps to a shared connection resolves to the owning `{ appId, connectionId }`, the same as the gallery row (ChatGPT for Codex's shared file).
A12 **An absent-app link shows what it did** (lens1 P4-R2-10, lens4 P4-R2-09). Preferred: reveal/scroll to the app's row without changing the search query. Otherwise the visible filter input shows the query with its Clear control. Test with a gallery already mounted with a prior search.
A13 **Unconfirmed-CLI probe analytics carry the originating account** (lens1 P4-R2-11, lens2 SEC-06, lens3 P4-R2-11, lens4 P4-R2-11): check the account after the `retryProbe` await; nothing is emitted under another account.
A14 **No fingerprint on mismatch either** (lens1 P4-R2-12, lens2 SEC-07): a generic signer-mismatch error; the test asserts neither fingerprint appears in failure output (exit code and cleanup unchanged).
A16 **User removal reported once** (lens3 P4-R2-12, lens4 P4-R2-10). Main's remove result says whether THIS call transitioned the record to removed; `AiConnectRemoved {by:'user'}` only then. Test two Disconnects while the revoke is pending.
