# Phase 3 code review, round 1 — adjudication (orchestrator)

Raw: scratchpad `reviews/p3-r1/lens1.md` (UX-xx), `lens2.md` (SEC-xx), `lens3.md` (P3-xx), `lens4.md` (Qxx). ~68 findings → the themes below. Read the raw findings for reproduction details. Every fix gets a regression test on the production path — for popup logic, test at the popup-to-flow boundary (the transitions the reviewers reproduced), not only the helpers. Simplest safe fix wins.

## High — credentials and consent
V1 **One operation from the first await** (UX-01, SEC-01, P3-01, Q01). Reconnect and Create key register the operation before their first await (`liveAccess`, `plan`) and carry it through plan → mint → deliver/record; check the cancel flag before every side effect. Test: close during the initial lookup → zero CreateApp.
V2 **Reconnect keeps its input** (UX-02, SEC-02, P3-03). Every reconnect continuation (quit consent, `plan`/`write/changed` back to the form, grantChanged) keeps the reconnect input: record, live grant, absolute expiry, name, route, tier. The form is prefilled from it, never from `DEFAULT_GRANT`. Immediately before minting — and again after any consent screen, before delivering an already-minted replacement — re-read the old key; if grant/expiry changed, release the undelivered replacement and show the updated access.
V3 **Replace is bound to what the user saw** (UX-03, SEC-03, P3-04, Q02). No `'fresh'` replace. Replace captures the displayed `{ targetPath, foreignDigest }` and carries it through retries and consent screens; a different digest, a different target, or an entry that vanished → fresh preview + a new Replace click. Manage's Replace first shows the fresh preview.
V4 **Moved location already owned** (UX-04, P3-05, Q03). Before offering "Connect this location", resolve the new canonical target; if an owned record exists there (e.g. ChatGPT at the default Codex home), open that record's Manage — zero mint/apply/revoke. Test the occupied-default case.
V5 **Disconnect tells the truth** (UX-05, SEC-12, P3-15, Q10). A removed record with outstanding hashes stays visible as "Revoke failed · Retry" immediately (do not wait for the next check). Leftover entry/extension copy is separate from the access sentence; "access ended / key deleted" only when `revoked` is true. Fix the two leftover strings that start with "The key is deleted".
V6 **Claude Desktop manual fallback** (UX-06, SEC-07, P3-09). With a pending key, Claude Desktop's manual route goes through `aiConnectApply({ manual: true })` with that key (it writes and verifies the key file); rotate/revoke only after main reports a commit. No generic "I've updated" for Claude Desktop.
V7 **Manual file setup records after the save** (UX-07, SEC-08, P3-08, Q05). For manual routes that put the key in a named file, the key stays pending while the user copies it; "I've updated <App>" records it (`aiConnectRecordManual` with `previewTarget` = the previewed canonical target, or the contract's empty target when none) and handles `fileMode`. Other-app (no known file) may record immediately.
V8 **Mint only with a usable fresh plan** (UX-08, SEC-09, P3-07, Q04). Create key requires the fresh plan to have a key-bearing manual step (or Claude Desktop's key-file preparation) and the same target as the displayed preview; prerequisite-only plans (install/update CLI) show the prerequisite + a Recheck, never mint. A refused target (`outsideHome` etc.) shows the reason, no mint. "I've updated" is enabled only when the current instructions are loaded; a `stale` reply that released the key clears the shown key.
V9 **Port re-read before apply** (SEC-04, P3-06). Re-read listening state + port immediately before `aiConnectApply`; if stopped/moved → back to preview with the pending key kept for retry/cleanup.
V10 **Running CLI candidates are never revoked by rotation or checks** (SEC-05). Hashes that are still unconfirmed/running are excluded from renderer revocation (rotation and check), until main settles them; explicit disconnect still revokes the complete set. Fix on whichever side is simplest (main must not hand them over as revokable, or the renderer filters) and test with the real main record shape.
V11 **Account binding** (SEC-06, P3-02). A check pass, a held key and its cleanup are bound to the account that started them; after each await, if the account/session changed, discard the result (no store update, no reconcile, no revoke under the wrong session). Deferred cleanup stays under the originating account.
V12 **Orphan registration failure keeps the reference** (SEC-10, P3-10). If revoke fails and `aiConnectOrphan` fails/unsaved/denied, keep `{ accountId, hash }` in memory and retry on the next check; show the Local API cleanup hint if it keeps failing.
V13 **Late CreateApp success** (SEC-11). A timeout reports a delay, but the operation stays attached to the real callback: a late success resolves the hash and is released (revoked/orphaned) if the flow was cancelled or abandoned; never silently dropped.
V14 **Desktop gate on key listing** (SEC-13). The shared key-listing helper (`keyFor`, `liveAccess`, reconnect, mint lookup) checks `isDesktop()` before calling heart. Test with the web/extension bridges.

## Medium — states and flows
V15 **Snapshot the submitted input** (UX-12, UX-13, P3-11, Q06, Q07). Capture the delivery input once on submit, including the absolute expiry; retries add only the new consent. A resumed same-key delivery (Continue → LM Studio file fallback etc.) builds its input from the stored connection (hash, tier, grant, name, expiry). LM Studio deeplink open error offers the settings-file fallback.
V16 **Unconfirmed CLI write** (UX-09). A record with an unresolved candidate stays in the waiting state ("Checking whether <App> saved it…") until a check resolves it; schedule that check (the popup promises one). Added/newSession only after promotion.
V17 **Install poll follows main** (UX-10, P3-12, Q11). After polling, route from the refreshed status + `nextStep` (toggle, restart, …); Added only when nothing is outstanding.
V18 **Acknowledgements and saves** (UX-11, P3-13, Q11). Advance a step only when `stepDone` succeeds; otherwise keep the step with a retryable error (no second restart). `recordSaved: false` (automatic and manual) shows the committed-but-unsaved notice with a save retry (via check/stepDone, whatever main supports).
V19 **Shared Codex restart target** (UX-14). When the adapter asks for a restart because ChatGPT reads the shared file, the instruction, `canRestart` and IPC id are ChatGPT's, not the creator card's.
V20 **Retry check = probe only** (UX-15, P3-17, Q09). Lookup failure ≠ absence: a failed `ListApps` returns a lookup error for that row; no `check()`, no reconcile, no heal, no revoke from this action.
V21 **Load failure is visible** (UX-16, P3-16). A failed load/first check shows the failure + Scan again (keeping previous data); an unknown installation state is not shown as "Not on this computer".
V22 **Manage reflects live evidence** (UX-17). A successful lookup with `present: false` shows Access ended + Reconnect; a conflict found by Disconnect shows Forget/Reconnect actions, not only text. A failed lookup is distinct from confirmed absence.
V23 **Claude relaunch failure and leftovers are shown** (UX-18, P3-18). `openFailed` and `left` are rendered in the restart view and in the `write/changed` path, not only in confirmInApp.
V24 **Manual setup includes the finishing instruction** (UX-19). When the plan's `nextStep` (restart/newSession/reload/toggle) is not already a step, show it as the last manual step.
V25 **Reveal / Open** (UX-20). Reveal only when the approved IPC target matches the step's path (else show a copyable path); hide Open where main can't launch (Linux) and surface `false` from Reveal/Open.
V26 **Focus stays in the popup** (UX-21, Q12). Minimal: labelled dialog root (`role="dialog"`, `aria-labelledby`), Tab/Shift+Tab contained while it's the topmost popup, root focused (tabIndex -1) while delivering, focus restored to the invoking control on close if simple.
V27 **Disconnect confirm race** (P3-14). Sequence the closes (`noCloseOnConfirm` or equivalent) so a fast disconnect can't restore the confirm popup.
V28 **Manage keeps unavailable spaces** (Q08). Use the Local API editor's `preserveUnavailableSpaces` handling for existing grants.
