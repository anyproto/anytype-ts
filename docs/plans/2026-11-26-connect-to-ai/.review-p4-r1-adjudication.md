# Phase 4 code review, round 1 — adjudication (orchestrator)

Raw: scratchpad `reviews/p4-r1/lens1.md`, `lens2.md`, `lens3.md`, `lens4.md`. The lenses are UX/spec, renderer security, state/robustness and conventions; ids overlap across files, so cite file+id. ~40 findings → Z1–Z14. ALL ACCEPTED. Each fix gets a regression test on the production path. History tests go through the app's own `keyboard.onBack` / `onForward` (or `checkForward`), not `history.goBack()`. Simplest safe fix wins.

## High
Z1 **A warm link is one history entry** (lens1 P4-02, lens2 UX-01, lens3 P4-02, lens4 P4-01). When the app is running with an account (any page, including `main/history`), an AI link dispatches straight to `Action.openAiApps({ app }, 'Deeplink')` without pushing the intermediate `main/aiConnect` page. Only a real cold start (no account/space yet) uses the bootstrap page. Back from the gallery returns to the previous page, and Forward goes back to the gallery without reopening a sheet. History is never reset.
Z2 **Canonical AI routes everywhere** (lens1 P4-03, lens2 UX-03, lens3 P4-01, lens4 P4-03).
- Canonicalize AI links at protocol ingress in main (`electron/ts/main.ts`, before storing the pending URL or sending it to a renderer). Store and forward only `/ai/connect?app=<catalog id>`.
- In the renderer, `redirectSet` and the router store the canonical form, never the raw string.
- Routes to `main/settings/aiApps` (incl. ones built by `Action.openAiApps` or reached through `anytype://main/settings/aiApps?...`) keep only allow-listed fields (`app` as a catalog id, `connection` as a connection-id shape, `route` from the allowed set). `key` and anything else is dropped before history, `updateTab` or saved tab state.
- Test with a `key=SENTINEL` through ingress, `redirectSet`, `Router.go` and `updateTab`.
Z3 **Cold start through PIN / account selection keeps the target** (lens2 UX-02, lens4 P4-03). The validated app target survives account selection and PIN unlock (e.g. a dedicated pending AI target that `onSpaceSwitch` doesn't clear, consumed once the authenticated gallery can open).
Z4 **Self-heal uses the real listening state** (lens1 P4-01, lens3 P4-06, lens4 P4-07, lens1 P4-09).
- Before a check that may repair (`apiListening: true`), verify the current API state from the source of truth (a fresh heart status RPC, or main), not a renderer cache another window may have made stale. Test: two windows, port change then disable → no rewrite.
- A check refused because the tab isn't active stays pending and runs on tab activation, with the live state.
- The startup callback rechecks its token + account after `await flow.load(true)` before `check('start')`.
- Non-desktop builds install no reaction at all (the guard goes before `reaction`).

## Medium
Z5 **One-shot target, consumed on arrival** (lens1 P4-07, lens2 UX-04, lens3 P4-02, lens4 P4-02). The gallery captures `app`/`connection` into page-local state and replaces the history entry BEFORE awaiting `flow.load()`. It opens the target only if that visit is still active, and drops it on navigation or account change. A failed first load keeps the target in memory, and a successful Scan again opens it.
Z6 **Pinned tabs** (lens1 P4-04, lens3 P4-05). The gallery target reaches the destination tab directly; no dependency on a dashboard `onRouteChange` callback that pinned-tab branches skip. A pinned origin tab keeps its route (no stranded loader page).
Z7 **Backlink after the opening check** (lens2 UX-05). Resolve `connection` against the list after the opening `check('open')` finishes; if reconciliation removed it, stay in the gallery (no empty Manage).
Z8 **A link for an absent app** (lens2 UX-06). Resolve the linked card with the gallery's detection state: an app that isn't installed gets the Get app / Set up manually offer, unknown → the scan recovery, never the automatic Connect form.
Z9 **Nudge eligibility at display time** (lens1 P4-06, lens2 UX-07/UX-08, lens3 P4-04, lens4 P4-04/P4-05).
- Main's queued `aiConnectClaimNudge` refuses when the account already has connections.
- On an eligible attempt (incl. focus retries), the renderer refreshes the account's list first.
- After a successful claim it rechecks the disposal token, account, focus, visibility and popup state right before `notify`. If it is temporarily ineligible, the claimed nudge is kept in that tab and shown when it becomes eligible.
Z10 **Strict analytics domains** (lens1 P4-08, lens2 UX-09, lens3 P4-03, lens4 P4-06). Each allowed field is validated against its finite domain: catalog ids; Open routes vs Start routes (separate sets); methods; steps; stages; categories; `by`. An event with a missing required field or an invalid value is dropped entirely, before transport AND debug log. Test the `analyticsEvent` broadcast path with a name/key-shaped value.
Z11 **Notification Close/Clear all: only the AI nudge is renderer-local** (lens1 P4-05). Middleware import/export notifications have `isLocal: true` and must still get `C.NotificationReply`. Skip the reply only for the renderer-created AI nudge (its id/type). Mixed Clear all test.
Z12 **Removal analytics once** (lens1 P4-10, lens2 UX-10, lens3 P4-09, lens4 P4-09). Main's serialized check returns the ids it transitioned to `removed` in that call; only those emit `AiConnectRemoved {by:'selfheal'}`. Persist on the record that this absence was reported, so a restart doesn't re-report; clear the marker when the entry reappears. A user Disconnect emits only after the account guard.
Z13 **Delivery analytics where the flow settles** (lens1 P4-11, lens3 P4-08, lens4 P4-08). `AiConnectDelivered` / `AiConnectProbeOk` / `AiConnectFailed` are emitted in flow.ts when the operation settles for the originating account, even if the sheet closed. UI-step events stay in the controller.
Z14 **Release signing hygiene** (lens3 P4-07, lens1 P4-12, lens3 P4-10).
- Windows: create the signing dir under `$RUNNER_TEMP`, remove inherited ACLs and grant only the runner user (`icacls`) before writing the PEMs. Keep umask on POSIX.
- `build-mcp.js` logs "signer verified" without printing the fingerprint.
